What this is

A marketplace repository. You add it once to your agent CLI, then install plugins by name. Each plugin is a self-contained bundle of slash commands, sub-agents, hooks, skills and — where it needs persistent state — its own MCP server.

Install

Add the marketplace once, then install whatever you need. Nothing is installed globally — every plugin is opt-in.

Claude Code

> /plugin marketplace add https://github.com/IvanLutsenko/awac-ai-agent-plugins
> /plugin install crashlytics        # then any plugin by name

Codex CLI

# add this repo as a Codex marketplace (Git source, or a local clone path)
$ codex plugin marketplace add IvanLutsenko/awac-ai-agent-plugins

# install a plugin: PLUGIN@MARKETPLACE
$ codex plugin add combined-review@awac-ai-agent-plugins

# verify
$ codex plugin marketplace list   # marketplaces and their roots
$ codex plugin list                # plugins and install status

Claude Code commands are converted into Codex skills under skills/generated-from-commands/, agents into skills/generated-from-agents/. The one exception is Locale Notifications — Claude Code only. The old repository slug awac-claude-code-plugins still works for existing installations.

The plugins

Versions below reflect the current release in the repository; the README in the repo is the authoritative changelog.

Crashlytics

Production v4.4.4 Claude Code + Codex

Turns a Crashlytics issue id into a report you can act on: what broke, which commit introduced it, who should fix it, and a before/after patch. Android and iOS, platform auto-detected from project config.

Pipeline

Four steps, each its own sub-agent, ending in a deterministic quality gate — the report is rejected if the forensics section is missing or the fix is not code-level.

> /crash-report ca8f7f21e3b4...

▸ crash-classifier-android   type, component, trigger
▸ firebase-fetcher           MCP: crashlytics_get_issue + batch_get_events
▸ crash-forensics-android    git blame on origin/<default-branch>
▸ validate-report.py         quality gate passed

Root cause  : view binding accessed after onDestroyView
Introduced  : 4f1a2b9 — "Move loader into fragment"
Assignee    : <blame author>
Fix         : cancel the collection job in onDestroyView (patch below)

Commands

  • /crash-report <id|console-url> — unified entry point, auto-detects platform
  • /crash-report-android, /crash-report-ios — explicit platform
  • /crash-config — language, branch, platform, model, Firebase ids
  • /crashlytics:install-permissions — one-time read-only allowlist, no more prompts mid-report

Notable

  • MCP-primary fetch with REST v1alpha fallback and a manual offline mode
  • Assignee identification is mandatory, not best-effort
  • Reports render with English headers and a body in any language
  • Firebase MCP launcher pinned to firebase-tools@15 so startup does not drift on silent major updates

Obsidian Tracker

Production v4.5.2 Claude Code + Codex

Makes an Obsidian vault the single source of truth for what you are working on: projects, a kanban board, bugs, architecture decision records and session logs. Hooks record sessions, actions and commits on their own — the tracking survives /compact.

A session

> /track-start kidkiosk
tracking on — session note created, PostToolUse hook recording

> /task kidkiosk "OTA update for the kiosk app"
TASK-007 created → Backlog

> /done kidkiosk 7
TASK-007 → Done

> /track-stop
session saved: 41 min, 12 actions, 2 commits, 1 decision

Commands

  • Projects — /projects, /project-new, /project-archive
  • Tasks — /task, /done, /today, /import
  • Bugs — /project-bug, /bug-close
  • Decisions — /decision-new, /decision-close, /decision-supersede, /decision-link
  • Context — /where-was-i, /pulse, /session-log

Notable

  • Own MCP server, builds itself on first run — no manual npm install
  • Board writes preserve %% kanban:settings %%, frontmatter and custom sections
  • Obsidian-safe filenames — mobile Obsidian and Sync stop complaining; a normalizer fixes existing vaults
  • Zero-padded, race-safe task ids (TASK-007)
  • 83 vitest + 86 bats tests behind it

Combined Review

Production v1.4.0 Claude Code + Codex

One command, four specialised reviewers in parallel, plus CodeRabbit CLI — findings merged, scored and de-duplicated instead of arriving as four separate walls of text.

Agents

> /review --base main

▸ code-reviewer            CLAUDE.md compliance, bugs, logic
▸ git-historian            reverted fixes, parallel-work conflicts
▸ silent-failure-hunter    swallowed errors, empty catch blocks
▸ test-analyzer            behavioural coverage gaps (criticality ≥ 7)
▸ coderabbit               CLI pass, auto-installed

confidence scoring 0–100 · low-confidence findings filtered out

Inputs it accepts

  • /review — uncommitted changes
  • /review 123 — GitHub PR or GitLab MR, forge auto-detected
  • /review !22 +threads — GitLab MR with inline resolvable threads
  • /review feature/X feature/Y — branch diff; --base main for current branch
  • Optional agents on demand: +comments, +types, +simplify

Auto Theme

Production v1.1.2 Claude Code + Codex

Your terminal agent follows macOS appearance. Switch the system to dark and the next prompt is already dark — in Claude Code and in Codex. Bundles two custom themes: gruvbox-light and sunset-drive.

How it works

# UserPromptSubmit hook, runs on every message
$ defaults read -g AppleInterfaceStyle      # Dark | (absent) = Light

light → gruvbox-light      dark → sunset-drive

~/.claude/settings.json   theme            # + ~/.claude.json mirror
~/.codex/config.toml      [tui] theme

# idempotent: no write when the theme already matches

Notable

  • Malformed configs and non-writable targets emit an explicit WARN: instead of failing silently
  • Unknown custom:* themes without a light/dark pair are preserved, not overwritten
  • /sync-theme forces a re-sync when you want it now

Locale Notifications

Production v2.0.1 Claude Code only

Native macOS notifications from Claude Code, in your system language. Detects the locale, translates once via Google Translate, caches the result and works offline from then on.

# Notification hook
$ defaults read -g AppleLocale            # ru_KZ, uk_UA, de_DE …
  → translate once → cache → osascript display notification

# custom messages via config file, project-local config resolves from hook cwd

Drawbridge

Beta v0.1.1 Claude Code + Codex

A bridge between a one-line brief and the image-gen web UIs you already pay nothing for. It writes a prompt tuned to the target model, puts it in the clipboard and opens the UI — no API keys, no billing.

> /draw закат на байкале с медведем у воды
target: gemini (default)  ·  brief auto-translated to English
prompt copied → opening Gemini Imagen 3

> /draw -t midjourney cyberpunk samurai   # one-shot target override
> /redraw -t chatgpt                     # same brief, another target
> /draw-prompt <brief>                   # prompt only, no browser

Notable

  • Per-target tuning: Imagen prose, DALL·E structure, Aurora density, Midjourney tag syntax
  • Settings in ~/.claude/drawbridge.local.md, overridable per project
  • History of the last 200 prompts feeds /redraw
  • macOS only in 0.1.1

Plugin Cross Port

Beta v0.10.1 Claude Code + Codex

The reason the rest of this marketplace is dual-target. It converts a plugin between Claude Code and Codex formats, then keeps both targets reconciled as the source changes — including the parts that cannot be derived mechanically.

# one-shot conversion, interactively
> Convert plugins/obsidian-tracker to Codex

# deterministic marketplace reconciliation
$ cross_port.py marketplace attach --source claude-code
$ cross_port.py marketplace sync
$ cross_port.py marketplace check

# semantic adaptations: plan first, then apply atomically
$ cross_port.py plugin adapt plugins/example
$ cross_port.py plugin adapt plugins/example --apply

Notable

  • CC → Codex: manifest conversion, commands/ → skills/generated-from-commands/, agents → standalone skills
  • Codex → CC: the same trip in reverse
  • Per-plugin .plugin-cross-port.json records the source of truth; stale critical adaptations mark a Codex target unavailable rather than shipping it broken
  • skills_authored flag lets hand-written Codex skills skip mechanical generation
  • Generated-output cleanup removes stale converted commands and skills

Clip Maker

Beta v1.3.1 Claude Code + Codex

A recording of a talk goes in, vertical clips with subtitles and ready social copy come out. Whisper for the transcript, Opus to pick the moments worth cutting, ffmpeg to cut them.

> /clip-maker ~/Downloads/my-talk.mp4

▸ transcribe      Whisper (local or API)
▸ find-moments    Opus ranks quotable segments from the transcript
▸ smart-crop      vision-based speaker detection → 9:16
▸ cut             ffmpeg + burned-in subtitles
▸ copy            captions for Shorts / Reels / TikTok

# or run a single stage
> /transcribe ~/Downloads/my-talk.mp4
> /find-moments ~/Downloads/transcript.json
